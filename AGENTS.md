# AGENTS.md — правила работы над сайтом «Меч Урала»

Этот файл читают ИИ-агенты и люди, которые правят сайт. Он объясняет, как устроен проект и что
можно менять, чтобы не сломать вёрстку, SEO и сборку. Человеческий quickstart — в
[README.md](README.md), картинки — в [PHOTOS.md](PHOTOS.md).

## 1. Что это за проект

Одностраничный лендинг турнира по историческому средневековому бою «Меч Урала» (бренд на
латинице — Ural Sword) в Перми. Турнир: **6 февраля 2027, СК «Сухарево», шоссе Космонавтов, 158А**.
Форматы: командные бои **5×5** и **12×12**. Вход для зрителей по билетам.

Стек: Angular 22 (standalone, сигналы, `@if`/`@for`), SSR + пререндер, SCSS, npm. Бэкенда нет:
страница статическая, все данные — в коде. Регистрация бойцов — отдельный проект.

## 2. Команды

| Команда                                                                        | Что делает                                              |
| ------------------------------------------------------------------------------ | ------------------------------------------------------- |
| `npm install` / `npm ci`                                                       | установка зависимостей                                  |
| `npm start`                                                                    | дев-сервер на http://localhost:4200                     |
| `npm run build`                                                                | прод-сборка в `dist/ural-sword` (проверка перед сдачей) |
| `npm run serve:ssr:ural-sword`                                                 | запуск SSR-сервера из готовой сборки                    |
| `npx prettier --check "src/**/*.{ts,html,scss}" README.md PHOTOS.md AGENTS.md` | проверка форматирования                                 |
| `npx prettier --write <файлы>`                                                 | автоформат (printWidth 100, одинарные кавычки)          |

Автотестов нет: `*.spec.ts` в проекте отсутствуют, `npm test` ничего не проверяет. Проверка
изменений = `npm run build` + визуальный просмотр страницы.

## 4. Как устроен блок

Каждый блок — папка `src/app/sections/<имя>/` с тремя файлами: `<имя>.ts` (компонент),
`<имя>.html` (шаблон), `<имя>.scss` (стили). Блоки подключаются вручную, без роутера:

1. `sections/index.ts` — `export * from './<имя>/<имя>'`;
2. `app.ts` — импорт и строка в массиве `imports`;
3. `app.html` — тег `<app-<имя> />` в нужном месте;
4. `header.ts` — ссылка `{ href: '#<id>', label: '...' }`, если блок должен быть в меню.

Порядок блоков: `hero → about → nominations → program → tickets → place → school → gallery`.
Порядок чередует фон: обычная секция (тёмная) → `section--muted` (светлее). Сохраняйте это
чередование, чтобы блоки не сливались.

Id секций: `#top` (hero), `#about`, `#nominations`, `#program`, `#tickets`, `#place`, `#school`,
`#gallery`. Ссылка в меню без такого id — битый якорь.

**Скрыть блок:** убрать тег из `app.html`, импорт из `app.ts` и ссылку из `header.ts` (иначе
якорь ведёт в никуда). Компонент при этом можно не удалять. Так сейчас скрыты `organizers` и
`partners` — они лежат в коде и вернутся, когда появятся данные.

**Вернуть скрытый блок:** тег в `app.html`, импорт в `app.ts`, ссылка в `header.ts`; для partners
и organizers фото/логотипы описаны в `PHOTOS.md`.

## 5. Правила контента

- Контент — по-русски, код и идентификаторы — по-английски.
- **Не выдумывать факты**: цены, телефоны, имена, адреса, расписание, количество участников.
  Нет данных — оставить заглушку или нейтральную формулировку («уточняем», «скоро»).
- Заглушки: в HTML — `&lt;текст&gt;` (экранированные угловые скобки), в TS — `'<текст>'`.
  Плейсхолдер должен быть очевиден: `<Имя Фамилия>`, а не «Иван Иванов».
- Если факт известен из анонса, используйте точные формулировки: «6 февраля 2027», «СК «Сухарево»»,
  «шоссе Космонавтов, 158А», «командные бои 5×5 и 12×12», «вход для зрителей по билетам».
- Типографика: «ёлочки» для названий, тире — (длинное), знак × в форматах (5×5, 12×12), не `x`.
- Бренд: в тексте «Меч Урала», в заголовке первого экрана и логотипе — `Ural Sword`.
- Списки (номинации, программа, галерея) держите массивами в `.ts`, а не копипастой в HTML.

## 6. Медиа

Всё готовое к публикации — только в `public/assets/`:

- `public/assets/img/` — фото блоков и служебные картинки;
- `public/assets/video/hero.mp4` — фон первого экрана.

Соглашение по именам: `about-1.jpg`, `about-2.jpg`, `about-3.jpg`, `nom-1.jpg`, `nom-2.jpg`,
`gallery-01.jpg` … `gallery-08.jpg`, `hero-poster.jpg`, `og-cover.jpg`, `logo.png`.

Оригиналы из мессенджеров и фотостоков — в `source-media/` (папка в `.gitignore`, в git и на
сайт не попадает). В `public/` кладём только обрезанные и сжатые файлы.

Картинки вставляются через компонент-слот:

```html
<app-photo class="nominations__photo" src="assets/img/nom-1.jpg" label="фото 4:3" alt="Бои 5×5" />
```

Пока файла нет (или он не загрузился), слот показывает зелёную плашку с подписью `label` —
вёрстка не «прыгает». Параметры: `src`, `alt`, `label`, `loading` (`eager` для первого экрана),
`fit` (`cover` для фото, `contain` для логотипов). Пропорции задаёт класс родителя через
`aspect-ratio` на самом элементе `app-photo`.

| Слот                             | Пропорции | Размер    |
| -------------------------------- | --------- | --------- |
| about-1 (большое)                | 16:9      | 1920×1080 |
| about-2, about-3                 | 1:1       | 1200×1200 |
| nom-1, nom-2                     | 4:3       | 1200×900  |
| gallery (квадратные)             | 1:1       | 1200×1200 |
| gallery-01, gallery-05 (широкие) | 2:1       | 2000×1000 |
| hero-poster                      | 16:9      | 1920×1080 |
| og-cover                         | 1200×630  | JPEG      |

Требования: JPG, sRGB, до ~300 КБ на фото; видео — H.264, 1920×1080, 8–20 с, без звука, до ~3 МБ,
`faststart`. Обрезка и сжатие:

```bash
ffmpeg -y -i source.jpg -vf "scale=1200:1200:force_original_aspect_ratio=increase,crop=1200:1200" \
  -q:v 4 public/assets/img/gallery-02.jpg

ffmpeg -y -ss 16.5 -t 8 -i source-media/hero-source.mp4 -an -vf "hqdn3d=2:1:3:3" \
  -c:v libx264 -preset slow -crf 30 -pix_fmt yuv420p -movflags +faststart public/assets/video/hero.mp4
```

Актуальный список кадров и что на них — в `PHOTOS.md`.

## 7. Стили и Angular-код

- Цвета, брейкпоинты, ширина контейнера и высота шапки — **только** в `variables.scss`.
  В компонентах: `@use 'variables' as v;` → `v.$color-accent`.
- Не хардкодить цвета и размеры в компонентах, не заводить второй источник палитры.
- Общие классы: `.container`, `.section` (`--muted`, `__title`, `__lead`), `.btn` (`--ghost`),
  `.card`. Блоки — по BEM-ish схеме: `.nominations__photo`, `.place__map`.
- Вёрстка mobile-first: базовые стили для телефона, дальше `@media (min-width: v.$bp-tablet)` и
  `v.$bp-desktop`.
- Angular 22: standalone-компоненты (без `standalone: true`), сигналы, `input()`, `viewChild()`,
  `@if`/`@for`. Не использовать `*ngIf`/`*ngFor` и `@NgModule`.
- SSR-safe: код выполняется и на сервере. Не обращаться к `window`, `document`, `matchMedia`,
  `IntersectionObserver` на верхнем уровне и в конструкторе — только внутри `afterNextRender`
  (пример — `hero.ts`).
- Не добавлять UI-библиотеки, CSS-фреймворки и новые зависимости без явной просьбы.

## 8. SEO и метаданные

- `src/index.html` — единственное место `title`, `description`, Open Graph и JSON-LD
  (Event + SportsOrganization).
- Меняете дату или площадку — обновите согласованно: `index.html` (meta + JSON-LD), `hero.html`,
  `about.html`, `program.html`. Даты в JSON-LD — ISO 8601 с часовым поясом Перми `+05:00`.
- Абсолютные URL (canonical, `og:url`, `og:image`, `@id`) сейчас указывают на GitHub Pages
  `https://sorryitsln.github.io/Ural_Sword/`. При переезде на свой домен заменить **все**
  вхождения в `index.html`.
- Страница пререндерится в статический HTML: важный контент должен быть в шаблоне, а не
  подгружаться только в браузере.

## 9. Деплой

Push в `main` → GitHub Actions (`.github/workflows/deploy.yml`) → GitHub Pages. Сборка идёт с
конфигурацией `production,github-pages`, `baseHref` — `/Ural_Sword/`. Поэтому пути к ассетам
только относительные: `assets/img/...`, `logo.svg`, без ведущего `/`. Не менять `baseHref` без
смены репозитория или домена.

## 10. Чек-лист перед сдачей

1. `npm run build` проходит без ошибок. Бюджеты: initial 500 КБ (предупреждение) / 1 МБ (ошибка),
   стили компонента 4 КБ / 8 КБ — не превышать.
2. `npx prettier --check` по изменённым файлам проходит.
3. Нет битых якорей: каждая ссылка `#...` в `header.ts` имеет секцию с таким `id`.
4. Нет случайных «undefined», пустых `alt` у содержательных фото, забытых заглушек без причины.
5. Вёрстка проверена хотя бы на 390 и 1440 px (мобильное меню, первый экран, сетки).
6. Медиа: правильные имена, пропорции, вес; `source-media/` и `dist/` не в коммите.
7. В ответе человеку: что изменили, где остались заглушки, какие данные нужны от организаторов.

## 12. Правила для ИИ-агентов

- Делайте минимальный дифф: не переписывайте блок целиком, если нужно поменять строку.
- Не меняйте палитру, шрифты, логотип, домен, название турнира и `baseHref` без явной просьбы.
- Не добавляйте зависимости и не запускайте `npm install <пакет>` без просьбы.
- Не делайте `git commit` / `git push` — коммитит человек. Стиль сообщений в репозитории:
  `feat: ...`, `fix: ...`, `docs: ...`.
- Не коммитьте `node_modules`, `dist`, `source-media`, `.DS_Store`.
- Не оставляйте фоновые серверы и занятые порты после проверки.
- Файлы читайте перед правкой; секреты и токены в репозиторий не добавляйте.
- Если данных нет — оставляйте заглушку, а не правдоподобную выдумку; перечисляйте такие места
  в ответе.
- После правок прогоняйте `npm run build` и сообщайте, если что-то не проверено (например,
  вёрстку не смотрели в браузере).
